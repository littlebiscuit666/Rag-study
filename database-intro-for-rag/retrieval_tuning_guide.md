# RAG 检索调参指南

本文档整理 BM25、向量召回、混合融合三层可调整的参数及其影响，方便调参参考。

## 一、BM25 参数

### 核心公式

```
score(Q,D) = Σ IDF(qᵢ) × [ f(qᵢ,D) × (k₁+1) ] / [ f(qᵢ,D) + k₁ × (1 - b + b × |D|/avgdl) ]
```

### 参数表

| 参数 | 默认值 | 取值范围 | 含义 | 调大的影响 | 调小的影响 |
|------|--------|---------|------|-----------|-----------|
| **k1** | 1.5 | 1.0 ~ 2.5 | 词频饱和度控制。控制 term frequency 对分数的增长上限 | 词频越高加分越多，长文档有优势 | 词频很快饱和，短文档更容易拿高分 |
| **b** | 0.75 | 0.0 ~ 1.0 | 文档长度归一化强度 | 文档长度影响更大，短文档更有优势 | 文档长度影响小，长文档表现更好 |
| **epsilon** | 0.25 | 0.1 ~ 0.5 | 负 IDF 修正系数（对极少出现的词做平滑） | — | — |

### 调参建议

- **短文本场景**（如搜索字段名、表名）：`k1=1.2, b=0.5` — 降低长度惩罚
- **长文本场景**（如整段描述）：`k1=2.0, b=0.75` — 词频区分度更大
- **中文一般默认即可**，如果发现过长的 chunk 总是排前面，把 b 调小

### 代码位置

```python
# bm25_retriever.py 的 _build_index 方法中
self.bm25 = BM25Okapi(self.tokenized_corpus, k1=1.5, b=0.75)
```

## 二、分词层面（jieba）

BM25 的效果很大程度上取决于分词质量。

| 可调项 | 说明 | 效果 |
|--------|------|------|
| **自定义词典** | 通过 `jieba.load_userdict()` 加载领域专有词 | 解决游戏领域词被错误切分的问题（如 "月卡"、"战令"、"PVP"） |
| **停用词过滤** | 去掉 "的/了/是/在/一个" 等无意义词 | 减少噪声，提升精准度 |
| **全模式 / 精确模式** | jieba.lcut 默认精确模式 | 精确模式适合检索；全模式召回率高但噪声大 |

## 三、向量召回参数

### Embedding 模型

| 模型 | 参数量 | 维度 | 速度 | 中文效果 | 适用场景 |
|------|--------|------|------|---------|---------|
| `BAAI/bge-small-zh-v1.5` | 33M | 512 | ⚡ 快 | ⭐⭐⭐ | 学习 / 快速迭代 |
| `BAAI/bge-base-zh-v1.5` | 102M | 768 | 🚶 中 | ⭐⭐⭐⭐ | 生产环境首选 |
| `BAAI/bge-large-zh-v1.5` | 330M | 1024 | 🐢 慢 | ⭐⭐⭐⭐⭐ | 追求最高质量 |
| `shibing624/text2vec-base-chinese` | 102M | 768 | 🚶 中 | ⭐⭐⭐ | 经典 baseline |

### 向量相似度度量

| 度量方式 | Chroma 配置 | 说明 |
|---------|------------|------|
| **cosine（余弦相似度）** | `hnsw:space: cosine` | 最常用，衡量向量方向差异，不受向量长度影响。**推荐** |
| l2（欧氏距离） | `hnsw:space: l2` | 衡量绝对距离，对向量长度敏感 |
| ip（内积） | `hnsw:space: ip` | 向量归一化后等同于 cosine，计算更快 |

### bge 模型专用参数

| 参数 | 默认值 | 含义 |
|------|--------|------|
| **query_prefix** | "为这个句子生成表示以用于检索相关文章：" | bge 系列模型训练时使用的 query 前缀，**必须加上**否则效果下降明显 |
| **normalize_embeddings** | True | 是否归一化向量。归一化后 cosine = 内积，检索更快更稳定 |

### 代码位置

```python
# vector_retriever.py
BGE_QUERY_PREFIX = "为这个句子生成表示以用于检索相关文章："

# 创建 collection 时
self.collection = self.client.create_collection(
    name=COLLECTION_NAME,
    embedding_function=self.ef,
    metadata={"hnsw:space": "cosine"},
)
```

## 四、混合融合参数

### 方式一：RRF 融合（推荐，默认）

```
score(chunk) = Σ 1 / (k + rankᵢ)
```

| 参数 | 默认值 | 取值范围 | 含义 | 调大的影响 | 调小的影响 |
|------|--------|---------|------|-----------|-----------|
| **rrf_k** | 60 | 10 ~ 100 | RRF 公式的 k 值，控制排名的权重曲线 | 排名曲线更平滑，低排名结果也能获得一定分数 | 头部排名权重极大，Top1 几乎决定一切 |

**经验建议：**
- 两个召回器质量接近 → `k=60`（默认）
- 一个明显比另一个准 → `k=20~30`（让更准的那个 Top 结果更有话语权）
- 召回器多（3个及以上）→ `k=60~100`（更平滑的融合）

### 方式二：加权融合

```
score = w_bm25 × norm(bm25_score) + w_vec × vec_score
```

| 参数 | 默认值 | 含义 |
|------|--------|------|
| **bm25_weight** | 0.5 | BM25 归一化后分数的权重 |
| **vector_weight** | 0.5 | 向量相似度的权重 |

**调参建议：**
- 关键词精确匹配更重要 → bm25_weight 调大（如 0.6）
- 语义理解更重要 → vector_weight 调大（如 0.6 ~ 0.7）
- 权重之和不一定非要等于 1，只是比例关系

### 候选集大小

| 参数 | 默认值 | 含义 |
|------|--------|------|
| **candidate_k** | 20 | 每个召回器返回多少个候选给融合阶段 |

- 设太小：可能漏掉只在一个召回器里排名靠后的相关结果
- 设太大：增加计算量，引入更多噪声
- 一般设 top_k 的 3~5 倍比较合适

### 代码位置

```python
# hybrid_retriever.py
retriever = HybridRetriever(
    method="rrf",       # 或 "weighted"
    rrf_k=60,
    bm25_weight=0.5,
    vector_weight=0.5,
)

results = retriever.search(query, top_k=5, candidate_k=20)
```

## 五、调参流程建议

### 第一步：准备评测集

先准备 10~20 个问题 + 标准答案（应该命中哪些 chunk），比如：

```json
[
  {
    "query": "战斗事件有哪些字段？",
    "expected_chunks": ["chunk_003", "chunk_001"]
  },
  ...
]
```

### 第二步：选评估指标

- **Recall@k** — Top k 结果中命中正确答案的比例（最常用）
- **MRR** — 第一个正确答案的排名倒数均值
- **NDCG@k** — 考虑排名位置的综合指标

### 第三步：调参顺序

1. **先调 BM25** — 加自定义词典、调 k1/b
2. **再调向量** — 换模型、确认 query 前缀正确
3. **最后调融合** — 试 RRF 不同 k 值，或加权不同权重

### 第四步：A/B 对比

每次只改一个参数，对比 Recall@k / MRR 变化，确认是变好还是变差。

## 六、常见问题

### Q: BM25 结果很差，关键词明明在文档里就是搜不到？

A: 检查分词。jieba 可能把领域词切错了（比如 "月卡" 被切成 "月/卡"）。加自定义词典解决。

### Q: 向量召回 Top1 总是不对？

A: 检查 bge 的 query 前缀加了没有。bge 系列不加前缀效果会下降很多。

### Q: 混合召回后反而不如单一路线？

A: 很可能两个召回器的质量差距太大。试试：
1. 把质量差的那个权重调低
2. 或者只用质量好的那个
3. RRF 模式下把 k 调小，让 Top 排名更有话语权
